## 기다리는 것 — 서버 썸네일 (thumbnail-render-worker)

다 만들어졌고(리뷰: 높은 위험 없음, 중간 3건 고침, 테스트 전부 통과) 이 Mac의
main에 합쳐져 있지만 **GitHub가 push를 거절**했어요: 이 Mac의 GitHub 로그인에
`workflow` 권한이 없어서 이미지 빌드 파일(`.github/workflows/images.yml`)을 바꿀
수 없어요. 아침에 터미널에서 한 번:

```bash
gh auth refresh -h github.com -s workflow
```

브라우저가 열리면 허락. 그다음 저한테 "푸시해"라고 하시면 push → 빌드 → 배포 →
서버 `.env`에 세 줄(`THUMBNAIL_RENDERER=server`, 비밀값, `COMPOSE_PROFILES=thumbs`)
→ 격리 확인(db/api/web에 닿지 않는지) → 썸네일 다시 만들기까지 할게요.
켜지 않으면 지금 방식(브라우저에서 찍기)이 그대로예요.

남은 위험 하나(알고 받아들인 것): Chromium 샌드박스를 뚫는 공격이 있으면 그
컨테이너 안에서 인터넷에는 나갈 수 있어요(DB·API에는 경로 없음). 필요하면
GCE 메타데이터 주소(169.254.169.254)를 그 컨테이너에서 막는 방화벽 한 줄을
나중에 더할 수 있어요.
