# API 분배 — 동아리 키 하나로 여러 회원이 쓰는 구조

(PART F2, 2026-10-14. 깊은 사양은 코드와 `docs/architecture.md`에 있고,
이 문서는 돈이 어떻게 지켜지는지를 운영자의 눈높이로 적습니다.)

## 1. 키는 누가 가지나

- **Anthropic 키는 동아리에 하나**, 서버의 `.env`에만 있습니다. 회원은
  키를 보지도 들고 있지도 않습니다 — 회원 화면의 모든 AI 기능은 우리
  백엔드를 거치고, 백엔드가 그 키로 호출합니다.
- 브라우저에는 키가 절대 가지 않습니다 (`NEXT_PUBLIC_*` 금지 규칙).
- 개발 PC에는 키가 아예 없어도 됩니다 — 모든 제공자는 mock이 기본입니다.

## 2. 사용은 어떻게 나뉘나

- 모든 호출은 **회원 한 명 + 분기 하나**에 귀속됩니다(`usage_events`:
  누가, 무슨 기능, 무슨 모델, 몇 토큰, 몇 원).
- **회원별 한도 = 그 회원의 동아리 지원 지갑** (기본 80,000원/분기).
  지갑이 비면 호출 전에 거절되므로, 한 회원이 다른 회원 몫을 쓸 수
  없습니다.
- 동아리 전체의 **최악의 경우** = 참여 회원 수 × 지갑 금액.
  - 40명 예시: 40 × 80,000원 = **3,200,000원/분기** (전원이 지갑을
    바닥까지 쓸 때). 달러로는 환율 1,400원 기준 약 $2,286/분기, 한 달에
    약 $762.
  - **예상치**는 비용 보정 데이터로 구합니다: Admin › AI Models › 비용
    보정의 "최근 실제" 답장 중앙값 × 회원들의 실제 사용 횟수. 베타
    초기에는 지갑의 10~20%만 쓰는 것이 보통이므로, 첫 구매는 최악의
    경우가 아니라 이 예상치로 잡고 모자라면 더 삽니다.

## 3. 한 회원(또는 한 사고)이 크레딧을 말리지 못하게 하는 것들

전부 **호출 전에**, 아무것도 쓰기 전에 거절합니다. 각각 테스트가
있습니다.

| 겹| 무엇 | 어디 |
| -- | ---- | ---- |
| 분당 횟수 | 1분에 10개(설정) — 스팸 방지 | `chat.check_rate_limit` |
| 답장 1회 비용 한도 | 기본 200원 (2026-10-14 아침 결정 — 100원으로는 페이지 읽기가 안 들어감), `max_tokens`로 미리 자름; 켜 둔 도구의 최악 비용(검색 요금+결과 토큰, 페이지 읽기 기본 1회×10,000토큰)을 미리 떼어 둠 | token-guard · chat-plus-tools · tool-cap-defaults |
| 하루 한도 | 회원마다, 모든 유료 기능 합산, KST (0=끔) | token-guard |
| 지갑 사전 확인 | 최악의 경우를 감당 못 하면 호출 안 함 | `usage.ensure_affordable` |
| **동시 호출 한도** | **서버 프로세스마다 동시에 N개까지만 제공자를 부름** (기본 3) | `provider_limiter` (PART F 신설) |

동시 호출 한도에 대해 솔직하게 적어 두면:

- Admin › System › 채팅 한도의 **동시 호출** 칸으로 바꿀 수 있고, 바꾼
  값은 재시작 없이 다음 호출부터 적용되며 감사 기록에 남습니다.
- 한도는 **프로세스 단위**입니다. 베타 서버는 uvicorn 워커 2개를
  돌리므로 실제 상한은 설정값 × 2 (기본 3 → 최대 6)입니다. e2-medium(2
  vCPU)에서 동시 스트리밍 6개면 충분히 여유 있고, 그 이상은 어차피
  느려집니다. 프로세스를 넘는 공용 카운터는 수십 명 동아리에는
  과설계라 일부러 안 했습니다.
- 자리가 없으면 10초까지 기다렸다가 "지금 CTRL+AI에 요청이 많습니다.
  잠시 뒤 다시 보내 주세요."로 거절합니다. 아무것도 차감되지 않고,
  이 거절은 우리 사정이므로 제공자 상태판에 기록되지 않습니다.

## 4. 동아리 크레딧이 바닥나면

- 회원: 한국어 안내 — "동아리의 Claude 크레딧이 바닥나 지금은 답할 수
  없습니다. 관리자에게 알려 주세요." **지갑에서는 아무것도 차감되지
  않습니다** (실패한 호출은 항상 무료 — Phase 2부터의 규칙).
- 관리자: **Admin › Dashboard** 맨 위에 빨간 카드 — 이제 이유까지
  적힙니다: "Claude — 크레딧 소진". (키가 틀리면 "키가 잘못되었거나
  만료".)
- 재시도 폭주는 없습니다: SDK 재시도는 1회로 묶여 있고(`max_retries=1`),
  우리 쪽엔 재시도 루프가 없습니다. 회원이 다시 보내면 그때마다 한 번
  호출하고 한 번 실패할 뿐입니다.
- mock이 `[mock-error:credit]`으로 이 전체 경로를 흉내 내므로, 키 없이
  테스트되어 있습니다.

## 5. 관리자가 보는 곳

- **회원별**: Admin › Budget의 지갑 표 (쓴 돈/남은 돈), 회원 상세.
- **제공자별**: Admin › Budget › 제공자별 사용액 — 다음 크레딧 구매의
  근거.
- **모델별·일별**: Admin › AI Models › 비용 보정(답장당 실제 비용)과
  캐시 절약(일별 적중률·아낀 돈).
- **이번 달 Anthropic 지출** (KST 달력 기준 — Anthropic Console의 월 한도는 자체 시간대(UTC로 추정)로 돌아 월초·월말에 몇 시간 어긋날 수 있습니다): `.env`에 `ANTHROPIC_MONTHLY_BUDGET_USD`를
  적으면 Admin › Budget 위에 진행 막대가 생기고 80%부터 경고합니다.
  실제 차단은 Anthropic Console의 월 한도가 하므로, 이 숫자는 Console
  한도보다 조금 작게 적어 먼저 알아차리는 용도입니다.

## 5-1. 비용 확인하는 법 (운영진용, cost-clarity 2026-10-14)

돈이 어디로 갔는지 확인하는 순서입니다. 모두 **Admin › Budget** 한
화면에 있습니다(위에서 아래로).

1. **크레딧을 사면 바로 적습니다** — 동아리 크레딧 › **구매 기록 추가**:
   제공자, 구매일, 받은 크레딧(USD), **카드에 실제로 찍힌 원화**(수수료와
   은행 환율 포함), 메모(예: "2026 Q4 첫 구매, 영수증 Concur 제출").
   기록은 고치거나 지울 수 없습니다. 틀렸으면 음수 금액과 "정정" 메모로
   한 줄을 더 적습니다. 감사 기록에도 남습니다.
2. **남은 크레딧(추정)** — 제공자 카드의 "남은 크레딧 = 모든 구매 − 장부에
   기록된 모든 사용"입니다. 우리 장부의 추정이고, **Anthropic Console ›
   Billing의 잔액이 최종 기준**입니다. 둘이 많이 다르면 6번으로 어느 날이
   다른지 찾습니다. "동아리 부담"은 회원에게 청구하지 않았지만 Anthropic은
   청구한 호출(중간에 끊긴 빌더 생성 등)입니다.
3. **지급 vs 사용** — 이번 분기에 회원 지갑으로 준 돈, 실제로 차감된 돈,
   아직 안 쓴 돈. 분기를 마감하면 "아직 안 쓴 돈"이 **회수**가 됩니다.
4. **회원별** — 지급(조정·이월 포함), 채팅 / 빌더 / 영상 / 기타로 쓴 돈,
   캐시로 아낀 금액. 한 회원의 지갑을 바꾸려면 그 줄을 눌러 회원 상세 ›
   **지원금 조정**: +/− 금액과 사유(필수). 덮어쓰지 않고 한 줄씩 쌓입니다.
5. **캐시** — 모델별·날짜별(KST) 적중률, 읽고 쓴 토큰, 아낀 금액. 같은
   대화를 5분 안에 이어 보내면 읽기가 생깁니다. Haiku 4.5는 앞부분이
   4,096토큰보다 짧으면 캐시하지 않으므로 짧은 대화의 0%는 정상입니다.
6. **Anthropic 비용과 대조(선택)** — 날짜 범위(UTC)를 고르고 **대조하기**.
   우리 장부의 `provider_cost`와 Anthropic 비용 보고서를 날마다 비교해
   1센트 또는 2%보다 차이 나는 날을 "다름"으로 표시합니다.
   - 기본은 **목업**이라 늘 "일치"입니다(화면에 그렇게 적혀 있습니다).
   - 진짜로 대조하려면 Anthropic Console › Settings › **Admin keys**에서
     Admin 키(`sk-ant-admin…`, 보통 API 키와 다름)를 만들고 서버 `.env`에
     `ANTHROPIC_ADMIN_PROVIDER=anthropic`, `ANTHROPIC_ADMIN_API_KEY=<키>`를
     넣은 뒤 `docker compose -f docker-compose.prod.yml up -d --force-recreate api`.
     둘 중 하나만 넣으면 서버가 켜지지 않습니다(설정 실수 방지).
   - Anthropic 보고서는 **조직 전체**입니다. Console의 Workbench나 다른
     프로젝트가 같은 계정에서 쓴 돈도 들어가 Anthropic 쪽이 조금 클 수
     있고, 몇 분 늦게 반영됩니다.
7. **CSV** — 회원별·날짜별(분기), 구매 기록, 캐시. Excel에서 한글이 바로
   열리도록 UTF-8(BOM)입니다. Concur 증빙에는 구매 기록 CSV와 회원별 CSV를
   씁니다.
8. **분기 마감** — Admin › Quarters › 그 분기 ⋯ › **분기 마감…**. 회원마다
   회수·이월 금액을 미리 보여 주고, 이월 비율(기본 0%)을 고른 뒤 확정합니다.
   모든 지갑이 멈추고, 이월분은 다음 분기 참여가 승인될 때 한 번 더해집니다.
   지우는 것은 없고 다시 열 수 없습니다. (**신청 마감**은 다릅니다 — 신청만
   닫고 분기는 진행 중이 됩니다.)

### 회원에게 하는 설명 (답장 영수증의 ⓘ와 같은 문장)

> 캐시는 지시문과 지난 대화처럼 매번 다시 보내는 앞부분을 Claude가 몇 분
> 동안 기억해 두는 기능이에요. 기억해 둔 부분을 다시 읽을 때는 처음보다
> 훨씬 싸게(모델에 따라 10분의 1~20분의 1) 계산되고, 처음 기억해 둘 때만
> 조금 더(1.25배) 들어요.

답장 아래 영수증은 입력 / 캐시 쓰기 / 캐시 읽기 / 출력 / 도구 / 합계를
원으로 보여 줍니다. 항목은 소수점까지의 실제 값이고, 합계는 그 합을
답장마다 1원 단위로 **올림**한 금액이라 항목을 더한 것보다 1원 안쪽으로
클 수 있습니다. Usage 화면에서 같은 항목을 대화별·날짜별로 볼 수 있습니다.

## 6. Anthropic Console 쪽 규칙 (운영자가 할 일)

1. **Auto-reload 끄기** — 잔액이 비어도 자동으로 더 사지 않게. 바닥나면
   위 4번 경로가 동작하고, 사람이 보고 삽니다.
2. **월 지출 한도 설정** — 키가 새어도 피해가 거기서 멈춥니다. 추천:
   예상치(위 2번)의 2배쯤, 그리고 `.env`의
   `ANTHROPIC_MONTHLY_BUDGET_USD`는 그보다 20% 작게.
3. **키는 운영용 하나만.** 개발은 mock으로 충분하므로 개발용 키는
   만들지 않는 것이 기본입니다(필요해지면 별도 키로 만들어 따로 한도).
4. **교체(로테이션)**: Console에서 새 키 발급 → 서버 `.env` 교체 →
   `docker compose -f docker-compose.prod.yml up -d --force-recreate api`
   → 옛 키 삭제. 노출이 의심되면 순서를 뒤집지 말고 즉시 옛 키부터
   삭제합니다(Chat이 몇 분 멈추는 쪽이 쌉니다).

## 7. 나중의 제공자들 (Higgsfield, DeepSeek 등)

같은 구조를 그대로 씁니다: 제공자마다 **동아리 키 하나**를 서버
`.env`에만 두고, 모든 호출이 같은 원장(회원+분기 귀속)에 기록되고,
같은 사전 확인·한도·동시 호출 제한을 지납니다. 제공자별 크레딧은
서로 옮길 수 없으므로 구매는 Admin › Budget의 제공자별 사용액으로
정합니다. DeepSeek은 미국 호스팅으로만 쓴다는 결정이
`docs/research/deepseek-research.md`에 있습니다.
